## The dialogue camera

The motion plan has three kinds: `static` (no input at all), `pan` (camera keys), `rotate` (middle-mouse drag)
(scripts/camera-plan.ps1). Every phase here is `static`: the runner sends nothing after the load, so nothing can
advance a dialogue. There is no click step: the queue cannot open a dialogue (as noted for cb7). BG3 does not save
during a dialogue, so the save must open it by itself on load (a trigger), or the run sees the exploration view.
The `static camera` gate (no `camera moving` scene-build line in any shot) makes a drifting or cutting dialogue
camera INVALID instead of comparing different shots. Open question for the user (docs/progress fragment of this
branch): does each save open its dialogue on load, and which character shows the shadow?
